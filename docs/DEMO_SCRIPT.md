# ReviewMind demo script

## Three-minute narrative

**0:00–0:20 — The problem**

“Teams remember that something was approved, but often lose why, where, and until when. ReviewMind brings that decision back into the next code review.” Point out the persistent **Synthetic demo** badge and labelled review time.

**0:20–0:55 — Learn the reason**

Open PR-A. Run Generic or Static first, then Memory. Give feedback on `transport-wrapper`: bridge-client 1.8 has a synthetic legacy wrapper compatibility issue. Set `src/adapters/legacy/**`, `>=1.8.0 <2.0.0`, effective 29 September, exclusive expiry 30 September, and require timeout 2000. Show the memory job, real reflection text, source event, and maintainer approval form.

Say: “Reflection drafts policy; it never approves it. Supabase records authority. Hindsight retains experience and retrieves it.”

**0:55–1:30 — Prove persistence**

Wait until the approved decision says **Memory · ready**. Click **Clear workspace** and rerun PR-A. Open the applicable evidence card. Show who approved it, why, path, version, expiry, prerequisite, and `event:<uuid>` source.

Say: “The browser state was cleared. This source came from a new Hindsight recall, then the server resolved it against the canonical ledger.”

**1:30–2:00 — Reject the wrong scope**

Run PR-B. Show the related evidence as `out of scope`; the wrapper convention remains a finding.

**2:00–2:25 — Expire the approval**

Run PR-D first and show the timeout finding survives the active wrapper exception. Then advance the labelled demo clock to 1 October and run PR-C. Show `expired`; history remains visible but grants no waiver.

**2:25–2:45 — Show uncertainty and measurements**

Run PR-E without a dependency version. Show the context question. Open Evaluation and show completed, failed, and not-run counts exactly as recorded. Do not quote an improvement percentage unless saved runs support it.

**2:45–3:00 — Explain the boundary**

“Hindsight finds experience. Supabase proves ownership and approval. Deterministic code checks path, version, time, prerequisites, conflicts, and revocation. The model explains evidence; it cannot grant an exception.” Name one limitation: synthetic data and a fixture-scoped timeout check.

## Live unseen-convention proof

After a completed review, choose **Teach an unseen convention**. Give a reason and exact supplied file path. Wait for feedback readiness and reflection. Approve the draft, wait for approval readiness, clear client state, and review a different input that triggers the same convention. This must use a real retained source; if providers are unavailable, show the explicit failure state and use a previously recorded genuine clip.

## Screening clip outline

- 0–10s: problem and single-sentence value
- 10–25s: feedback → reflect → approval, with real source identity
- 25–40s: clear state → fresh recall applies on PR-A
- 40–52s: PR-B out of scope and PR-C expired
- 52–60s: timeout survives; architecture and measured result

## Recording checklist

- Record at 1280 px or wider with the browser console clean.
- Hide bookmarks, notifications, secrets, and `.env`.
- Capture the provider status, ready state, source event, and fresh-session action.
- Keep failed or delayed states honest; do not edit them out and imply a successful live call.
- Export, replay, and check audio, text legibility, and all links before upload.
